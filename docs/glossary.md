# Glossary

Terms used in the domain and in the documentation. Alphabetical order.

## A

**ADR (Architecture Decision Record)**
Short, immutable record of an architectural decision, with context and consequences. They live in
[`adr/`](./adr/README.md).

**Artifact**
File generated by the pipeline for an application: resume in HTML/PDF, cover letter, email,
recruiter message, answer suggestions. The content lives in `applications/`; the database keeps
only metadata (`kind`, relative path, mime, size).

**`applications/`**
v1's directory where the artifacts live. v2 references this directory via `APPLICATIONS_DIR`,
without copying the files.

## B

**`base_profile/`**
Directory with the extracted base resumes (text + metadata) per stack and language. Imported into
the `profiles` table.

## C

**Checkpoint**
See **Run**.

**Compatibility layer**
Routes and DTOs that translate the v2 domain into the format the v1 UI consumes. They live in
`src/api/dto/legacy.ts` and `src/api/routes/compat.ts`. Temporary.

## D

**Document-shaped**
Model in which complex aggregates (`Fit`, `JobSnapshot`) are stored as JSON in a column instead of
normalized tables. Eases migration to a document database. See
[ADR-0002](./adr/0002-document-shaped-model.md).

**DTO (Data Transfer Object)**
Response/input structure of a route. The legacy DTO is v1's format; the new DTO is the domain's
`Job`.

## F

**Fit**
Alignment assessment between candidate and job. Contains `rating` (0–100), `analysis`, `dimensions`
(`skillsMatch`, `experienceMatch`, `logisticsMatch`, `cultureMatch`), `strengths`, `gaps`,
`eligibility`, `languageGate` and `logisticsNote`.

**Hybrid fit**
v1's engine that combines deterministic rules with an LLM. Not yet ported to v2.

## J

**Job**
A registered application. In v2, `jobs` is the single source of truth for company, role, status,
language, stack and fit.

**JobSnapshot**
Copy of the job data at processing time: title, company, location, URLs, detected language,
`content` (scraped text), `extraQuestions` and `recruiterMessage`.

## L

**Legacy**
Everything that belongs to v1: its single-file UI, its server, the JSON data files and the
`dd/mm/yyyy` format.

## M

**Migration**
Versioned SQL script in `drizzle/` that changes the schema. Applied by `pnpm db:migrate` or on
boot.

## O

**Orphan run**
Run whose `job_id` is `NULL` because the corresponding job no longer exists. Valid and expected:
17 of the 34 imported runs are in this state.

**`owner_id`**
Field present in `jobs` to prepare for multi-user. Today it is always `local`.

## P

**Profile**
Base resume per stack (`ruby`, `php`) and language (`pt-br`, `en`). Keeps the original JSON in
`content`.

## R

**Repository pattern**
Layer that isolates the domain from the database. Contracts in `src/repositories/types.ts`; SQLite
implementation in `src/repositories/sqlite/`. Allows swapping the database without touching
routes. See [ADR-0003](./adr/0003-repository-pattern-and-cloud.md).

**Run / Process**
Checkpoint of a processing run. Stores stage, URL, language, flags, error, fit and snapshot. It can
exist without a job (`job_id = NULL`), preserving history.

## S

**Setting**
Key/value pair in `settings`. Used for `pdf_theme` and `candidate_form`.

**Stack**
Main technology of the resume/job: `ruby` or `php`. Defines which base profile is used.

**Strangler**
Strategy of replacing v1 by parts, keeping it functional until the last slice migrates. See
[ADR-0004](./adr/0004-strangler-strategy-v1-compatibility.md).

## T

**TanStack Query**
Data cache and synchronization library planned for Phase 2.

## V

**Vitest**
Test runner used in the project.
