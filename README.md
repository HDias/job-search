# Job Search Assistant v2

Incremental rewrite of the v1 app: **API + SQLite + React now, cloud later**.
v1 stays intact as a fallback. Full documentation lives in [`docs/`](./docs/README.md).

## Status

- [x] Phase 0 — data model, normalization and import script for the JSONs
- [x] Phase 1 — SQLite + Drizzle, repositories, HTTP routes and compatibility with the v1 UI
- [x] Tests — 64 backend + 23 frontend
- [ ] Phase 2 — React: dashboard, detail and admin done; checkpoint response missing
- [ ] Phase 3 — Turso/Supabase/Firestore adapter

## Stack

| Layer | Choice |
|---|---|
| Runtime | Node.js 24 |
| Database | SQLite (`better-sqlite3`) + Drizzle ORM |
| Validation | Zod |
| Backend | Express 5 + TypeScript |
| Frontend | React 19 + Vite 6 + TanStack Query + React Router |
| Testing | Vitest + Supertest + Testing Library |
| TS execution | `tsx` |

## Commands

```bash
pnpm install
pnpm dev                 # API on http://localhost:3344
pnpm dev:web             # React on http://localhost:5173 (proxy to the API)
pnpm build:web           # build in web/dist
pnpm start               # API + SPA on http://localhost:3344
pnpm typecheck           # backend
pnpm typecheck:web       # frontend
pnpm test                # backend
pnpm test:web            # frontend
pnpm db:migrate          # apply migrations to data/job-search.db
pnpm db:import           # import v1's JSONs (paths default to the v1 app, see below)
pnpm db:import --reset   # wipe and re-import
```

Import options (`<legacy-dir>` is the v1 project directory):

```bash
pnpm db:import \
  --tracker <legacy-dir>/job_search_tracker.json \
  --processes <legacy-dir>/job_processes.json \
  --applications <legacy-dir>/applications \
  --base-profile <legacy-dir>/base_profile \
  --db data/job-search.db \
  --reset
```

## Data model

- `jobs` — one row per job. `fit`, `strengths`, `gaps`, `eligibility` etc. live in `fit_json`
  (document-shaped, no excessive normalization).
- `runs` — processing checkpoints (Playwright/LLM), linked to `jobs` via a **nullable** `job_id`.
  Old runs whose job no longer exists stay valid with `job_id = null`.
- `artifacts` — metadata for PDFs/HTMLs/TXTs. The file stays on disk; the database only keeps the
  relative path and the MIME.
- `profiles` — base resumes per `(stack, language)`.
- `settings` — PDF theme, computed profile, form data. **API keys are not imported.**

### Decisions that ease the move to the cloud

- Dates in **ISO 8601** (v1 used `dd/mm/yyyy`).
- Prefixed IDs (`app_`, `proc_`, `art_`) with UUID — they work as doc IDs in Firestore.
- `owner_id` already exists (default `local`): avoids a backfill when auth arrives.
- No `undefined`: missing fields become `null`.
- Data access only via interfaces in `src/repositories/types.ts`. Swapping SQLite for Turso,
  Supabase or Firestore means implementing another class, without touching the UI.

## API

Main REST (new format):

| Method | Route | Description |
|---|---|---|
| GET | `/api/health` | health check |
| GET | `/api/stats` | totals per status, average fit, applications in the last 30 days |
| GET | `/api/jobs?status=&q=&limit=&offset=` | paginated list |
| GET | `/api/jobs/:id` | job + runs + artifacts |
| POST/PATCH/DELETE | `/api/jobs` and `/api/jobs/:id` | CRUD |
| GET | `/api/runs?jobId=&stage=` | checkpoints |
| GET/POST/PATCH/DELETE | `/api/runs` and `/api/runs/:id` | CRUD |
| GET/PUT | `/api/profiles/:stack/:language` | base resumes |
| GET/PUT | `/api/settings/:key` | generic settings |

Compatibility with the v1 UI:

- `GET/PUT/DELETE /api/applications[/:id]` — legacy DTO (`dd/mm/yyyy` date, `fitRating`,
  `cvPdfFile`, `fitDimensions`, `languageConfirmation`…).
- `GET/PUT/DELETE /api/processes[/:id]` — checkpoints in the legacy format (`job`,
  `jobSnapshot`, `applicationId`, flattened fit).
- `GET/PUT /api/base-resumes`, `/api/pdf-theme`, `/api/candidate-data`.
- `/applications/*` (static), `/cv/:id` and `/extras/:id/:view`.
- Heavy processing routes (Playwright/LLM: `/api/process-job`, `/api/fit-check`, etc.) stay in v1
  for now.

## Frontend

| Route | Screen |
|---|---|
| `/` | Dashboard with stats, search, status filter and pagination (state in the URL) |
| `/jobs/:id` | Fit, processing runs, artifacts, summary and status change |
| `/admin` | Base resumes, PDF appearance and form data |
| `*` | Not found page |

In development, run `pnpm dev` and `pnpm dev:web` in separate terminals. Vite proxies `/api`,
`/applications`, `/cv`, `/extras` and `/base_profile` to port `3344`.

In production, `pnpm build:web && pnpm start` serves the SPA on the same port as the API, with a
fallback to `index.html` that doesn't swallow the 404s of `/api` and the artifacts.
